# 品味规则（rules）

从 `ledger.md` 归纳而来，可被 `lint-style`、关键帧自检直接引用。
**上限 7 条**，超了先合并或删；每条都要能判定对错，不能只是形容词。

状态说明：`已确认` = 有明确判断记录支撑；`待验证` = 推断，需再用几次确认。

---

## R1 参考图 ≠ 可实现质量　｜已确认

风格参考若是 3D 网格、粒子、光照、材质、辉光渲染出来的，先用目标管线出一版样帧再决定；做不出来就换，不要「先做完整片再想办法」。

- **判定**：风格源文件含 `hidden-line` / `bloom` / `volumetric` / `particle` / `PBR` 等描述，而管线只能二维矢量 → 必须先出样帧验证
- **违反表现**：照抄配色却做不出质感，画面发灰、线毛、无纵深

## R2 关键帧先行　｜已确认

新风格或新章节，未见 3 张关键帧（信息最密 / 最空 / 最复杂）不得开工整章；每轮最多修 3 个问题，3 轮不过换风格。

- **判定**：提交评审时若没有 `out/keyframe-*.png` → 不合格
- **图表自检**：含图表的镜头另抽成图后的关键帧；逐一对照原始内容，检查图形、数据、坐标轴及单位、刻度、图例、标签、来源等所需元素是否完整准确，确保未裁切、遮挡或重叠。动态揭示须同时检查首帧、中间帧和完成帧，确认不会出现误导性的残缺图表；发现问题修复后复渲。
- **违反表现**：整章做完才发现风格不成立

## R3 单帧可读性　｜待验证

缩到 50% 尺寸，仍能读出主体是什么、标题层级是什么。

- **判定**：截图缩至 960×540 后目视，说不出主体 → 不合格
- **标题位置**：同类画面的主标题共用固定的安全区、对齐线与垂直锚点；相邻镜头并排检查，标题不因文字长度、换行或主体变化上下跳动。章节封面等确需不同层级的画面可使用统一的独立版式，但不得随意漂移。
- **违反表现**：全尺寸好看，一缩小糊成一片

## R4 颜色克制：三个色相，各有语义　｜待验证

单帧除黑、白、灰外不超过 3 个色相；每个色相固定一个语义（红 = 结论 / 当前这一步，蓝 = 流 / 实时，赭 = 磁盘 / 资源），不按章节换色。层次靠同色相的不同明度与饱和度：纸色四阶、墨色三阶、同色淡底（veil），不靠新增色相。

- **判定**：数单帧主要色相，>3 即超；同一语义出现两种颜色，或同一颜色承担两种语义 → 不合格
- **层次判定**：画面至少有两档纸色或墨色参与分区（交替行、信息带、内存区）；全片只有一种纸色、所有块只靠描边区分 → 判为平
- **违反表现**：每章各自加色，整片看下来像不同片子；或为怕单调而堆颜色，画面变成调色盘

## R5 信息密度　｜待验证

单帧信息块 ≤5 个（并列信息组口径，框架层不计），留白 ≥30%；一帧只讲一件事，标题即结论。
**留白 30% 是下限，不是目标。** 各镜头的主体规模、文字层级和有效信息量应保持整体均衡；允许按叙事节奏有意疏密变化，但不能出现相邻画面一边过满、一边像未完成。图表按内容和理解需要补齐数据层，不为凑密度虚构数据或增加装饰文字。

- **判定**：数独立信息块（标签、图表、说明段），超 5 即拆帧；将全片各镜头关键帧并排比较，检查是否有内容明显单薄、文字过少或过密的画面，并结合口播和信息池补全必要信息或拆帧，不以元素数量或像素覆盖率强行凑数。
- **文字取舍**：每个小标题、角标和标注须有明确的信息、分类或定位作用；与主标题、字幕或邻近文字重复，或者只作装饰而无助理解的，删除。必要的数据标签、单位、图例和来源保留，避免因删减损害图表理解。
- **违反表现**：观众不知道先看哪；或画面单调乏味、只搬版式外壳不搬信息结构
- **口径**：框架层（页眉规则线 / 栏目名 / 期号 / 免责小字 / 脚注 / 来源 / 署名 / 发丝网格 / 批注箭头）不计入信息块

## R6 动效克制　｜待验证

缓动只用 `easeOutCubic` 一类单向减速；禁回弹、弹跳、旋转入场，除非风格本身要求盖章式的硬切。

- **判定**：代码里出现 `spring` / `bounce` / `back` 缓动且风格未要求 → 不合格
- **违反表现**：技术图解配弹性动效，显得轻浮

## R7 单一真源　｜已确认

风格参数（色值、字体、动效）只存在于 `style/tokens.css` 与风格源文件，不抄进提示词、不硬编码在组件里。

- **判定**：组件出现 `#` 开头的颜色字面量，或提示词里重复 tokens → 不合格
- **违反表现**：源文件一改，提示词/组件里的旧值就过期

---

## 维护

- 每累计约 10 条 `ledger` 记录，归纳一次：新增、合并、或删除
- 连续 3 个项目都没触发过的规则，删掉
- 规则之间冲突时，以「用户当次明确指令」优先，其次以编号小的优先
